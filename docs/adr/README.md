# Architecture Decision Records

Use an ADR for any material change to authentication, authorization, session handling, data storage, proxy trust, cryptography, secrets, rate limiting, deployment topology, CI identity, artifact provenance, or other security boundary.

Each ADR should include: context, decision, security consequences, alternatives considered, migration/rollback impact, and validation evidence. Number files sequentially as `NNNN-short-title.md`. Accepted ADRs are immutable except for spelling/link corrections; superseding decisions create a new ADR that references the old one.
